# تطوير صفحة الدردشة إلى «محرّك إدارة المنصة»

الهدف: أن يتوقف النموذج عن كونه مجرد محادثة نصية، ويصبح مساعداً يقرأ بيانات المنصة الحقيقية، ينفّذ مهام مركز الاتصال، ويقوم بعمليات كتابة (تفعيل سائق، إضافة مطعم، تعديل أسعار…) **بعد موافقتك اليدوية فقط**.

## 1. طبقة الأدوات (Tools) — عقل المساعد

توسعة دالة `ai-admin-chat` لدعم استدعاء الأدوات (function calling) بدل البث النصي فقط. الأدوات تنقسم لعائلتين:

**أدوات قراءة — تُنفَّذ فوراً بدون تأكيد**
- `platform_overview`: طلبات اليوم، رحلات نشطة، سائقون متصلون، مداخيل، نسبة الإلغاء.
- `search_orders` / `search_rides`: بحث بالرقم المرجعي، الحالة، المدينة، التاريخ.
- `driver_status`: حالة سائق، اشتراكه، تقييمه، آخر موقع، ساعات عمله.
- `store_lookup`: بحث المطاعم/المحلات وحالتها ونسبة العمولة (بدون كشف البريد/الهاتف — عبر القناة الآمنة الحالية فقط).
- `call_center_queue`: الطلبات المعلّقة أكثر من ٥ دقائق، المكالمات المفتوحة، الشكاوى غير المعالجة، قائمة العملاء المحتملين للاتصال.
- `health_report`: أخطاء العملاء الأخيرة، فشل الدوال، صحة النظام.

**أدوات كتابة — تتطلب تأكيداً يدوياً**
- `set_order_status` / `assign_driver`: معالجة طلب عالق أو إسناده لسائق (مهمة مركز الاتصال).
- `activate_driver` / `set_driver_type`: تفعيل أو تعطيل دور سائق.
- `create_store` + `create_menu_item`: إضافة مطعم وتعبئة قائمته وأسعاره.
- `update_pricing`: تعديل معاملات التسعير في إعدادات المنصة.
- `update_prospect_call`: تسجيل نتيجة مكالمة مع عميل محتمل وتحديث حالته.
- `create_notification`: إرسال إشعار لسائق أو عميل.

## 2. آلية التأكيد اليدوي

عندما يقرر النموذج تنفيذ عملية كتابة:
1. تُسجَّل العملية كـ«أمر معلّق» في جدول الأوامر مع وصفها بلغة واضحة والبيانات الدقيقة التي ستتغيّر.
2. تظهر داخل الدردشة **بطاقة موافقة**: عنوان العملية، الجدول المستهدف، قيمة قبل/بعد، وزرّا «تنفيذ» و«رفض».
3. عند الضغط على «تنفيذ» فقط، تُنفَّذ العملية على الخادم (وليس من المتصفح)، ثم يُعاد الناتج للنموذج ليُكمل جوابه.
4. كل تنفيذ ورفض يُسجَّل في سجل التدقيق باسمك والوقت والقيمة السابقة.

لا يوجد أي مسار يسمح بالكتابة بدون مرور بهذه البطاقة.

## 3. صفحة جديدة: «صلاحيات المساعد»

صفحة في لوحة المدير (تحت مجموعة الذكاء الاصطناعي) تعرض جدول كل الأدوات:
- الاسم، الوصف، النوع (قراءة/كتابة)، مفتاح تفعيل، ومستوى الخطورة.
- خيار «تنفيذ تلقائي بدون تأكيد» لأدوات القراءة فقط، معطّل بشكل دائم لأدوات الكتابة.
- حدود يومية: أقصى عدد عمليات كتابة في اليوم.
- تخصيص الأدوات لكل وكيل (وكيل مركز اتصال ≠ وكيل مالي).
- سجل مباشر لآخر العمليات المنفّذة والمرفوضة.

## 4. تحسينات صفحة الدردشة نفسها

- **شريط جانبي للمحادثات**: استئناف أي محادثة سابقة، عنوان تلقائي من أول رسالة، بحث، حذف.
- **تحكّم في الردود**: زر إيقاف البث، إعادة توليد، نسخ، تحرير آخر رسالة وإعادة الإرسال.
- **أوامر سريعة**: `/تقرير` `/طلبات-عالقة` `/سائق` `/مطعم-جديد` `/صحة-النظام`.
- **بطاقات نتائج**: عرض نتائج الأدوات كجداول وبطاقات مختصرة بدل نص خام، مع طيّ التفاصيل.
- **رفع ملفات وصور**: صورة وثيقة سائق أو قائمة مطعم لاستخراج البيانات وتعبئتها في نموذج جاهز للتأكيد.

## 5. الاستهلاك والتكلفة

تسجيل كل طلب في سجل الاستهلاك (النموذج، عدد التوكنات، الزمن، التكلفة التقديرية) مع حدّ يومي قابل للضبط، ولوحة صغيرة أعلى الدردشة تعرض استهلاك اليوم.

## التفاصيل التقنية

- **الخادم**: توسعة `supabase/functions/ai-admin-chat/index.ts` لحلقة أدوات (tool loop) مع بثّ الأحداث؛ ودالة جديدة `ai-admin-execute` لتنفيذ العملية المعتمدة بمفتاح الخدمة بعد التحقق من دور المسؤول ومن أن الأمر بحالة «معلّق» ويخصّ صاحبه.
- **قاعدة البيانات**: إعادة استخدام `smart_assistant_commands` (حالة/قبول/رفض) لسجل العمليات المعلّقة، و`smart_assistant_audit_log` للتدقيق، و`ai_usage_log` للاستهلاك؛ إضافة جدول `ai_tool_permissions` لصفحة الصلاحيات، وعمود لربط العملية بالمحادثة والرسالة. كل الجداول بسياسات RLS للمسؤول فقط + منح صلاحيات صريحة.
- **الواجهة**: تفكيك `AiAdminChat.tsx` إلى مكوّنات (شريط المحادثات، الرسائل، بطاقة الأداة، بطاقة التأكيد، شريط الإدخال) مع الحفاظ الكامل على نظام الثيمات والتخصيص الحالي.
- **الأمان**: لا تنفيذ كتابة من المتصفح إطلاقاً؛ التحقق من الدور داخل الدالة؛ قوائم بيضاء للجداول والأعمدة المسموح بها لكل أداة؛ لا SQL حر؛ حدّ يومي للعمليات.
- **النموذج**: `openai/gpt-5.6-sol` عبر بوابة Lovable AI مع `reasoning_effort: "none"`، مع الإبقاء على إمكانية اختيار أي نموذج مفعّل من الجدول.

## ترتيب التنفيذ المقترح

1. جداول الصلاحيات والعمليات المعلّقة + سياسات الوصول.
2. أدوات القراءة + حلقة الأدوات في الدالة + بطاقات النتائج.
3. آلية التأكيد اليدوي + دالة التنفيذ + سجل التدقيق.
4. صفحة «صلاحيات المساعد».
5. الشريط الجانبي للمحادثات وتحكّم الردود والأوامر السريعة.
6. تسجيل الاستهلاك والحدود اليومية.
