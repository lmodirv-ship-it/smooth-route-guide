# منارة — شبكة تبادل المعرفة بين مواقع مجموعة HN

الفكرة: تصبح صفحة **منارة** نقطة اتصال موحّدة بين كل مواقع وتطبيقات مجموعة HN. عندما يتغيّر نطاق أو عنوان أو مسار في أي موقع، يرسل الموقع "شيفرة" (Signal) إلى المنارة، فتُسجَّل في **جدول التصدير** عند المُرسِل وفي **جدول الاستيراد** عند المُستقبِل. كل واجهة تحافظ على هويتها وتصميمها، ويتغيّر فقط ما يخصّ العناوين والروابط.

هذا يحلّ المشكلة التي ذكرتها: فتح تطبيق الحاسوب أو الهاتف وظهور واجهة موقع آخر — لأن كل تطبيق سيقرأ عنوانه الصحيح من المنارة قبل التوجيه.

## ما سيُنشأ

### 1) جدولان في قاعدة البيانات
**`manara_exports` (التصدير)** — كل شيفرة يُصدّرها هذا الموقع للمجموعة:
- الموقع المصدر، نوع الشيفرة (`domain_change` / `route_change` / `status` / `announcement` / `asset`)، المفتاح، القيمة القديمة، القيمة الجديدة، الحمولة JSON، المواقع المستهدفة، التوقيع، الحالة (`pending`/`delivered`/`failed`)، التوقيت.

**`manara_imports` (الاستيراد)** — كل شيفرة واردة من مواقع المجموعة:
- الموقع المرسل، معرّف الشيفرة الأصلية، النوع، المفتاح، القيمة، حالة المعالجة (`received`/`applied`/`ignored`/`rejected`)، سبب الرفض، التوقيت.

مع فهارس، `GRANT`، تفعيل RLS: قراءة عامة محدودة للشيفرات المنشورة فقط، والكتابة للمسؤولين أو عبر دالة خادمية موقّعة.

### 2) دالة خادمية `manara-sync`
نقطة استقبال/إرسال موحّدة:
- `POST /publish` — الموقع يعلن تغيير نطاق أو مسار ⇒ يُسجَّل في `manara_exports` ويُنسخ كـ import لكل موقع مستهدف.
- `GET /pull?site=...` — الموقع يسحب الشيفرات الجديدة الخاصة به.
- `POST /ack` — تأكيد التطبيق (تحديث الحالة إلى `applied`).
- تحقّق بمفتاح مشترك (توقيع HMAC) لمنع أي إرسال مزيّف.

### 3) الواجهة داخل صفحة `/manara`
تصميم يحافظ على الكرة المضيئة الحالية ويضيف حولها طبقة "شبكة المجموعة":
- **مدارات المواقع**: كل موقع من HN يظهر كعقدة مضيئة تدور حول الكرة، لونها يعكس حالتها (متصل / متأخر / خطأ).
- **نبضات ضوئية** تسير على خط بين العقدة والمركز عند وصول أو إرسال شيفرة — الاستيراد يدخل نحو المركز، التصدير يخرج منه.
- **شريط سجل حي** أسفل الكرة (اختياري التفعيل) يعرض آخر الشيفرات بصيغة مختصرة.
- كل ذلك بـ CSS/framer-motion فقط، ويحترم `prefers-reduced-motion`، ولا يمسّ باقي تصميم الصفحة.

### 4) لوحة الإدارة
تبويب جديد **"شبكة منارة"** داخل إعدادات الإدارة:
- جدولان (استيراد / تصدير) بالبحث والتصفية وإعادة الإرسال والحذف عبر `AdminCrudTable`.
- زر "إعلان تغيير نطاق" يرسل شيفرة يدويًا لكل المجموعة.
- تحديث لحظي عبر Realtime.

### 5) الربط بالتطبيقات
- خطّاف `useManaraNetwork` يقرأ الشيفرات المطبَّقة ويخزّن العناوين الفعلية محليًا.
- عند الإقلاع، `domainFailover` وقائمة نطاقات التطبيق تُغذّى من المنارة بدل القيم الثابتة فقط — فيفتح كل تطبيق واجهته الصحيحة دائمًا.

## تفاصيل تقنية
- ملفات جديدة: `src/hooks/useManaraNetwork.ts`، `src/components/manara/ManaraNetworkOrbit.tsx`، `src/components/manara/ManaraSignalLog.tsx`، `src/admin/pages/ManaraNetwork.tsx`، `supabase/functions/manara-sync/index.ts`.
- ملفات تُعدَّل (إضافة فقط، بدون حذف): `src/pages/Manara.tsx`، `src/admin/AdminRoutes.tsx` + رابط الشريط الجانبي، `src/lib/domainFailover.ts`.
- الهجرة إضافية بالكامل: جدولان + فهارس + GRANT + سياسات RLS + `REPLICA IDENTITY FULL` للجدولين لدعم Realtime.
- كل النصوص عبر نظام i18n دون نصوص مكتوبة مباشرة.

## المراحل
1. الهجرة (الجدولان + الأمان) ودالة `manara-sync`.
2. الخطّاف + واجهة المدارات والنبضات في `/manara`.
3. تبويب الإدارة والسجل الحي.
4. ربط `domainFailover` والتطبيقات + اختبار شيفرة تغيير نطاق من طرف إلى طرف.
