# واجهة الزبون الجديدة + استوديو الواجهات

## 1. إعادة بناء واجهة طلب الرحلة (`/customer/ride`)

بناء الشكل الموجود في الصورة المرسلة، بنفس الترتيب:

```text
[ شريط علوي مصغّر: أفاتار • مشاهدات • مستخدمين • طلبات اليوم • الرصيد • جرس • لغة ]
[ بطاقات صغيرة: الوجهة | نقطة الانطلاق | رقم اللوحة | نقاط النشاط | طلب رحلة ]
[ ============ الخريطة الكبيرة (أكبر عنصر) ============ ]
[ خيارات إضافية: نوع الرحلة | عدد الركاب | طريقة الدفع | ملاحظات ]
[ بطاقة التكلفة التقديرية 15-25 DH • الزمن • المسافة ]
[ شريط الأمان: رحلتك آمنة • دعم 24/7 • مشاركة الرحلة • تتبع مباشر ]
[ احجز لاحقاً |  طلب سائق الآن (زر أخضر-أزرق عريض) ]
[ شريط سفلي: الرئيسية • الرحلات • طلب رحلة • الرسائل • الحساب ]
```

مبادئ التنفيذ:
- الخريطة الحالية (Leaflet) تبقى كما هي وظيفياً، فقط تكبر وتأخذ أزرار (+/-) وزر «موقعي» و«تحديد على الخريطة».
- البطاقات العلوية مختصرة، والمساحة أسفل الخريطة قابلة للتوسّع لمزايا لاحقة.
- كل النصوص عبر نظام i18n (بدون نص ثابت)، والألوان عبر رموز التصميم في `index.css` (لا ألوان صريحة).
- لا حذف لأي منطق حالي: نفس دوال حساب السعر، إنشاء الطلب في `ride_requests`، والتوجيه إلى التتبع.

## 2. المزايا المطلوبة — على مرحلتين

مرحلة أولى (تُنفَّذ الآن، مرتبطة بقاعدة البيانات):
- نوع السيارة: اقتصادية / عائلية / VIP / كهربائية → جدول `ride_vehicle_types` (اسم، أيقونة، مُعامل سعر، مفعّل) + حفظ الاختيار في `ride_requests`.
- عدد الركاب + الملاحظات + طريقة الدفع → أعمدة إضافية على `ride_requests`.
- التكلفة التقديرية كمجال (من–إلى) والزمن والمسافة، محسوبة من إعدادات التسعير + معامل نوع السيارة.
- جدولة الرحلة لاحقاً (زر «احجز لاحقاً») → عمود `scheduled_at`.
- مشاركة الرحلة + زر الطوارئ → جدول `ride_safety_contacts` ورابط مشاركة عام لرحلة محدّدة.
- القسائم والنقاط: ربط بأنظمة `coupons` و`reward_stars` الموجودة داخل بطاقة السعر.

مرحلة ثانية (تُجهَّز مساحتها في الواجهة، وتُنفَّذ بعد اعتماد المرحلة الأولى):
- مقارنة أسعار السائقين وتقييم السائق قبل القبول.
- محادثة ورسائل صوتية مع السائق (تعتمد على نظام الدردشة الحالي المقيّد).
- مساعد ذكاء اصطناعي يقترح أفضل نقطة انطلاق ووقت.
- الطقس وتأثيره على مدة الرحلة.
- توصيل الطرود من نفس الشاشة.

## 3. استوديو الواجهات (لوحة المدير)

صفحة جديدة `/admin/ui-studio` باسم «استوديو الواجهات»، تتحكم في شكل كل الواجهات:
- اختيار التخطيط لواجهة الزبون: `classic` (الحالي) أو `studio` (النموذج الجديد) — مع إمكانية إضافة نماذج لاحقاً.
- التحكم في العناصر: إظهار/إخفاء الشريط العلوي، بطاقة الأمان، الشريط السفلي، بطاقة الخيارات الإضافية، أزرار الخريطة.
- ضبط الشكل: نصف قطر الحواف، كثافة المسافات، شدّة التوهج، لون الإبراز (من رموز التصميم فقط)، حجم الخريطة.
- معاينة مصغّرة داخل الصفحة قبل الحفظ، مع أزرار «تطبيق» و«استرجاع الافتراضي».
- النطاق: إعدادات لكل واجهة (زبون / سائق ركاب / سائق توصيل / متجر / مركز اتصال).

الربط: كل الواجهات تقرأ الإعداد عبر hook موحّد مع تحديث فوري (Realtime)، فأي تغيير في الاستوديو يظهر مباشرة في كل الصفحات دون إعادة بناء.

## التفاصيل التقنية

- قاعدة البيانات (إضافي فقط، بدون حذف):
  - `ui_studio_settings`: `scope` (customer/driver/delivery/store/callcenter) فريد، `layout`، `options` (jsonb)، `is_active`، طوابع زمنية. قراءة عامة للجميع، تعديل للمدير فقط (`has_role`)، مع GRANT صريح وتفعيل RLS و`REPLICA IDENTITY FULL` للبث الفوري.
  - `ride_vehicle_types`: قراءة عامة للأنواع المفعّلة، تعديل للمدير.
  - أعمدة إضافية على `ride_requests`: `vehicle_type`, `passengers`, `notes`, `payment_method`, `scheduled_at` (كلها اختيارية بقيَم افتراضية حتى لا تتأثر الطلبات الحالية).
  - `ride_safety_contacts`: مملوكة للمستخدم عبر `auth.uid()`.
- الكود:
  - `src/hooks/useUiStudio.ts`: قراءة `ui_studio_settings` + اشتراك Realtime + قيم افتراضية عند فشل الاتصال.
  - `src/pages/customer/RideStudioLayout.tsx`: التخطيط الجديد مقسّم إلى مكوّنات صغيرة (`RideTopBar`, `RideQuickCards`, `RideMapPanel`, `RideOptionsBar`, `RideFareCard`, `RideSafetyStrip`, `RideCTA`).
  - `src/pages/CustomerPage.tsx`: يبقى كما هو ويُستخدم كتخطيط `classic`، ويختار بين التخطيطين حسب الإعداد.
  - `src/admin/pages/UiStudio.tsx` + تسجيل المسار في `AdminRoutes.tsx` ورابط في `AdminLayout.tsx` تحت زر Themes.
  - مفاتيح ترجمة جديدة في `src/i18n/locales/*` للعربية والفرنسية والإنجليزية والإسبانية.

## طريقة العمل
1. ترحيل قاعدة البيانات (الجداول والأعمدة والسياسات).
2. بناء المكوّنات والتخطيط الجديد وربطه بالبيانات.
3. بناء صفحة استوديو الواجهات وربط كل الواجهات بها.
4. تجربة على مقاس الهاتف (393px) بالعربية والفرنسية مع لقطات شاشة للتأكد.
